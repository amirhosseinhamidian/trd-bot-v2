# R3-01 - برش نامزد انتشار محلی v0.3.0

وضعیت: **پیاده سازی شده؛ پذیرش نهایی روی SHA مالک مخزن باقی است**

این مرحله پس از Freeze موفق P5-09، نسخه محصول را از `0.2.0` به `0.3.0` ارتقا می دهد و یک نامزد
انتشار محلی می سازد. این مرحله قابلیت محصولی، migration، endpoint یا مجوز عملیاتی تازه اضافه
نمی کند.

## پیش شرط قطعی

فایل `artifacts/p5-09/phase-five-acceptance.json` باید:

- با parser رسمی Phase 5 بدون خطا خوانده شود؛
- `ready_to_freeze_phase_five=true` و `failed_gates=[]` داشته باشد؛
- benchmark قطعی و CI موفق Candidate پذیرفته شده را ثبت کرده باشد؛
- در ancestry نامزد انتشار وجود داشته باشد.

## قرارداد نسخه

مقدار `0.3.0` باید در همه منابع زیر یکسان باشد:

- `pyproject.toml`؛
- `src/trd_bot/__init__.py` و مقدار پیش فرض API؛
- `.env.example`؛
- `frontend/package.json`؛
- root package در `frontend/package-lock.json`؛
- تست های release backend و frontend.

`tests/test_release_version.py` و `frontend/src/app/__tests__/release-readiness.test.ts` هرگونه
واگرایی را fail می کنند. `tests/test_v0_3_release_cut.py` نیز رکورد P5-09 و مرز عملیاتی نسخه را
برای Release Cut کنترل می کند.

## مرز انتشار

- فقط `RESEARCH`، `BACKTEST`، `PAPER` و `SHADOW` مجاز هستند.
- Market Data فقط از providerهای public و read-only دریافت می شود.
- Risk و Portfolio Intelligence فقط evidence و پیشنهاد شبیه سازی شده تولید می کنند.
- credential صرافی، private account API، wallet، deposit/withdrawal و live order خارج از محدوده اند.
- tag، GitHub Release، deploy، merge به `main` و مدیریت دارایی واقعی در این مرحله انجام نمی شوند.

## گیت های محلی

ابتدا قرارداد Release Cut:

```bash
python -m pytest \
  tests/test_release_version.py \
  tests/test_release_security_boundary.py \
  tests/test_phase_five_acceptance.py \
  tests/test_v0_3_release_cut.py \
  -q
```

سپس گیت های کامل:

```bash
python -m ruff format --check .
python -m ruff check .
python -m mypy
python -m pytest -m "not integration"
```

```bash
cd frontend
npm run format:check
npm run lint
npm run typecheck
npm run test
npm run build
```

چرخه migration و integration باید فقط روی PostgreSQL 17 یک بارمصرف با نام دقیق
`trd_bot_test` اجرا شود. حذف volume دیتابیس توسعه مجاز نیست.
